# Запросы к коллекции · занятие 1

**Предметная область:** заявки в сервисную службу (тикеты)
**База и коллекция:** `helpdesk.tickets`
**Сколько документов:** 5 документов (`seed.json`)

Документ заявки: номер, дата создания, заказчик во вложенном объекте
(`customer.name`, `customer.contact`), приоритет, статус, плановые часы и
массив тегов. Форма документов намеренно разная: у `t-004` внутри `customer`
есть ещё телефон, у `t-005` есть поле `comment`, которого нет у остальных,
а у `solution` в трёх документах пустое значение `null`.

---

## 1. Точное совпадение строки

```js
{ customer.name: "Сомова" }
```

Найдено: **1 из 5**
Что искали: заявки заказчика «Сомова». Заявка `t-003` подошла, а `t-002`
с заказчиком «ИП Сомова» — нет: строка должна совпасть целиком.

## 2. Поле внутри вложенного объекта

```js
{ "customer.contact": "somova@example.ru" }
```

Найдено: **1 из 5**
Что искали: заявку по почте контакта. Поле `contact` лежит внутри `customer`,
поэтому путь к нему пишется через точку.

## 3. Элемент массива

```js
{ tags: "печать" }
```

Найдено: **2 из 5**
Что искали: заявки с тегом «печать» среди прочих тегов — `t-002` и `t-005`.

## 4. Оператор сравнения

```js
{ hours: { $gt: 3 } }
```

Найдено: **2 из 5**
Что искали: заявки, на которые планируется больше трёх часов. Так как `hours`
хранится числом, `$gt` сравнивает его с числом 3.

## 5. Наличие поля

```js
{ comment: { $exists: true } }
```

Найдено: **1 из 5**
Что искали: заявки с комментарием. Поле `comment` есть только у `t-005`.

## 6. Сломанный запрос

```js
{ hours: { $gt: "3" } }
```

Что произошло: **пустой результат** — не ошибка разбора, кнопка Find нажалась.

Как это видно на экране: Compass показывает `0 – 0 of 5` при том, что запрос
синтаксически верный и поле `hours` есть у всех документов.

Почему так: в `hours` записаны числа, а в условии — строка `"3"`. Операторы
сравнения сравнивают только значения одного типа, поэтому число с числом
сравнилось бы, а число со строкой — нет, и ни один документ не подошёл.
Чтобы проверить, что дело в типе, запрос `{ hours: { $type: "number" } }`
находит все пять документов, а `{ hours: { $type: "string" } }` — ни одного.

## Цена дубликата

В каждом документе повторяется название заказчика: `ООО «Вектор»` есть и в
`t-001`, и в `t-004`, а у заказчика Сомовой заявки в двух документах: «ИП Сомова»
(`t-002`) и «Сомова» (`t-003`).
Повторяется ещё статус и приоритет: значения `высокий` и `в работе`
встречаются в нескольких документах.

Если заказчик переименовал фирму, а документов станет двести, название
придётся менять в двухстах местах, и за один проход это вручную не проверить:
легко пропустить документ и получить в отчётах и «ООО «Вектор», и «Вектор».
Часть таких правок не находится поиском и заменой, если написание
в документах успело разойтись.

Повтор оставлен, потому что название заказчика не меняется само по себе:
это справочные данные, а не событие. Дубликат нигде не нужно пересчитывать,
а обращений по одной заявке немного — при выборке заявки вместе с заказчиком
не требуются дополнительные запросы, как при ссылке на отдельную коллекцию
`customers`. Когда фирм станет много и их названия начнут путаться,
справочник заказчиков вынесут в отдельную коллекцию со ссылкой
`customer_id`, но это уже модуль 2.
